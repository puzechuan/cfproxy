- 修复生产环境 500（用户贴出 Cloudflare 错误日志：签名过期的 release-assets URL 返回 500）：
  - 根因：`buildResponse` 直接把 `upstream.status` 传给 `new Response()`；上游网络层失败时 fetch 返回 `Response.error()`（status=0），触发 `RangeError: Responses may only be constructed with status codes in the range 200 to 599`，被最外层 catch 变成 500。已用 workerd 实测 `Response.error().status === 0` 证实。
  - 修复：新增 `normalizeStatus()`，把非法 status 收敛为 502，文本改写与二进制透传两处都改用规范化后的 status。
  - 新增 `isSignedAsset()` + `expiredSignatureResponse()`：一次性签名链接（release-assets / objects + sig/jwt 参数）遇到 403/404/status 0 时返回 410 HTML 提示页，引导用户回到干净的 `/https://github.com/用户/仓库/releases` 链接重新获取新签名，不再暴露含义不明的 500。
  - 新增 3 项回归测试（status 0 → 502、签名链接 403 → 410 提示页、签名有效 → 200 不受影响），共 13 项全部通过。
  - 本地 `wrangler dev --remote` 因环境代理干扰不可用（ProxyWorker internal error），改由 vitest/workerd 验证。
