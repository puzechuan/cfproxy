## 无浏览器登录脚本 `public/cfproxy-login.sh`

- 从历史提交 `2278b5e` 恢复了登录脚本（当时随「64 位访问密钥」功能一起被 `234741d` 回滚），按现在的接口重写：`POST /api/login` → 会话 Cookie 存成 Netscape 格式，`~/.cfproxy.cookie` 权限 600。
- 参数：`-u 用户名 / -p 密码 / -b 站点 / -f cookie 文件 / -t 只打印 token / -q 安静模式 / -h`；支持 `CF_USER`、`CF_PASS`、`CF_BASE`、`CF_COOKIE` 环境变量，cron/CI 用 `-q`。
- 比旧版多的：登录后用 cookie 回查一次 `/api/me` 确认会话真的可用；临时文件清理改成 `rm -f` + `rmdir`，不用 `rm -rf`（受限环境会被拦）。
- **`.gitattributes` 加 `*.sh text eol=lf`**：CRLF 会让 shebang 变成 `bash\r`，Linux 上跑不起来；测试里也断言了 `body.includes("\r") === false`。
- 本地可直接下载：`http://127.0.0.1:8799/cfproxy-login.sh` 返回 `application/x-sh`（约 7.4 KB）。`.sh` 不在 `run_worker_first` 名单里，由 assets 直接吐，所以测试要问 `env.ASSETS.fetch`——走 `worker.fetch` 会被当成代理目标报「域名不在白名单」。
- 推送前线上 `GET /cfproxy-login.sh` 返回 **401**：文件还没部署，assets 找不到就落到 Worker 的代理分支去要登录态。部署完成后应变成 200，需要复验。
- 实测：本地 + 线上登录均成功，`-t` 取 token、密码错误返回 1 并打印服务端文案、拿 cookie 请求代理返回 200，`npx vitest run` 75 项通过。

- 本机没有 sshpass，用 `SSH_ASKPASS_REQUIRE=force` + 一个回显密码的小脚本免交互登录，`scp -P 6222` 传文件即可。
- 结果：登录成功（`testadmin` admin）、cookie 权限 600、`curl -b` 代理 200、`wget --load-cookies` 下载成功、`git -c http.extraHeader="Cookie: cfproxy_session=$(脚本 -t)" clone` 成功、密码错误 exit 1、`env -i`（PATH 清空）下也能跑、目标目录不存在会自动 `mkdir -p`。
- **发现并修掉的坑**：`curl -c` 把 HttpOnly Cookie 写成 `#HttpOnly_域名` 开头的行，curl 认得这个前缀，**wget 却把 `#` 开头当注释跳过**，同一份 cookie 文件在 wget 下直接 401。脚本现在写完文件后用 awk 去掉该前缀（curl 不需要它），三件工具就通吃了。
- 推送 `05469ce` 后自动构建完成，线上 `GET /cfproxy-login.sh` 由 401 变 **200（8142 字节，与本地 md5 一致）**，可在服务器上直接 `curl -fsSLO` 安装。
